# Fixture provenance and rules

This folder holds the byte-parity net of the compiler: the input workspaces and the golden outputs that the
instrumented VB6 compiler produced from them. Nothing here is generated by the C# port, and nothing here may
be regenerated by it.

## Layout

```
Fixtures/
├── Corpus/                 The golden corpus, one workspace per folder (see Corpus/README.md)
├── Quirks/                 The quirks golden: its own Workspace/ and VB6 Outputs/ (see Quirks/README.md)
├── Run-VB6Corpus.ps1       Compiles the corpus and the quirks workspace with NG Center
├── Stock/                  The stock TRLE Objects.h, for tests that compile against it (see below)
├── Workspace/              Input workspace (used as the engine folder when compiling)
│   ├── script/             SCRIPT.TXT, English.txt, #INCLUDE files, ExtraNG @file
│   ├── Objects.h           Slot/static constants
│   ├── PluginDemo.script   The plugin constants of the Plugin= line
│   ├── extras/             ImportFile= payloads (demo007.bin)
│   └── pix/                Image fixtures (image1.bmp; @image4.bmp already encrypted)
└── VB6 Outputs/
    └── <seed>/             Golden Script.dat + English.dat for one seed of the testing guide
```

`Workspace/` is the input of the seeded goldens that [the testing guide](../../docs/TESTING.md#fixtures)
lists, and [its page](Workspace/README.md) gives its layout.

`Stock/Objects.h` is a byte-for-byte copy of the stock TRLE `Objects.h` that every corpus workspace holds,
such as `Corpus/NgArrays/Workspace/Objects.h`,
whose SHA-256 is `e25e3a496f7c5f6c0854ffcf9c009edd767ecca9e626bced7a5c8879c57dbfed`.
`TestFixtures.StockObjectsHPath` points to it, so a test that compiles against the stock constants reads a
file that no golden workspace shares. Like the goldens, it is never edited or regenerated.

The `LastCompilerLog.txt` and `run-info.txt` files under `VB6 Outputs/99999/` of each corpus workspace and of
`Quirks/` are provenance that no test reads.

## Golden provenance (the instrumented VB6 build)

The NG security block holds random padding that [PD-07](../../docs/PARITY-DECISIONS.md) records, so pristine
VB6 output is not reproducible byte-for-byte. The seeded golden sets of
[the testing guide](../../docs/TESTING.md#fixtures) were produced by the
maintainer's **instrumented VB6 copy**, which injects a fixed seed immediately before the
security block is written. The seed is 99999 in the NG Center build that produces the corpus and quirks
outputs, whose folders `VB6 Outputs/99999/` carry it as their name:

- `Original Compiler/Progetti/NG_Scripter/Module1.bas:8414`: `g_DeterministicSeed = 99999`
  directly before `Call AggiungiHeaderSecurity`.
- `Original Compiler/MioModulo.bas:850-857`: `Casuale`, which draws the security block's padding, calls
  `Randomize g_DeterministicSeed` once per process (`m_DeterministicSeeded`) when the global is non-zero,
  instead of the original `Randomize`.

**Seed-injection procedure:** set `g_DeterministicSeed` to the target
value, run the VB6 compiler against the `Workspace/` fixture, and store the resulting
`Script.dat` + `English.dat` under `VB6 Outputs/<seed>/`. The maintainer's instrumented copy of the VB6
source retains the line with the injected seed, and a clone lacks that copy
([VB6 citations](../../CONTRIBUTING.md#vb6-citations)). This instrumentation is *not* original behavior,
and [PD-07](../../docs/PARITY-DECISIONS.md) records why the port's default injects no seed.
[The procedure](../../docs/PRODUCING-VB6-OUTPUTS.md) runs this build over the corpus.

The port mirrors the injection test-only through `TRNGCompilerOptions.DeterministicSeed`.

## What is compared byte-for-byte

`GoldenParityTests.SeededCompile_MatchesTheVb6Outputs` (category `Parity`, one data row per seed of
[the testing guide](../../docs/TESTING.md#fixtures)):

1. Checks the SHA-256 of every file in `Workspace/` but its notes,
   and of the shipped `scripter_constants.txt`, against the hashes the test holds.
   It names each input that changed, such as a text file whose line endings git converted,
   and each file added or removed.
2. Copies `Workspace/` to a temp directory and compiles it with `DeterministicSeed = seed`.
3. Compares `Script.dat` against `VB6 Outputs/<seed>/Script.dat`, byte-for-byte.
4. Compares `English.dat` against `VB6 Outputs/<seed>/English.dat`, byte-for-byte.

`GoldenParityTests.UnseededCompile_MatchesTheVb6OutputsOutsideTheSecurityBlock` compiles the same inputs
without a seed, as a release build does. It compares every byte outside the NG security block with each
golden, and checks the block's length, checksum, copied fields and padding against the VB6 writer.

Run them with `Run-Parity.ps1` (`PARITY PASSED` on success) or
`dotnet test --filter TestCategory=Parity`.

**Rule for byte-comparing tests:** [the testing guide](../../docs/TESTING.md#conventions) owns it, under
*Byte comparisons*.

## Adding new edge-case coverage

The seeded goldens of `Workspace/` are **never regenerated**. A behavior that only VB6 can settle goes
into a corpus workspace for the owner's next NG Center run (see `Corpus/README.md`); any other new behavior is
pinned by a *hand-derived* expectation:

1. Read the relevant VB6 source (cite file + line in the test).
2. Derive the expected bytes (or exact words/fields) by hand from that source.
3. Assert those exact bytes/words in a focused test and reference the
   `docs/PARITY-DECISIONS.md` row(s) it enforces.
4. Never mutate the existing `Workspace/` inputs or `VB6 Outputs/` goldens, because the goldens
   guard every other change in the repository.
